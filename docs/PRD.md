# PRD — 구석메모 다음 개발 사이클

## 1. 목적·사용자·배경

- **제품**: 구석메모 — 화면 가장자리 인덱스 손잡이로 여는 Windows 메모 앱
  (Tauri 2 + WebView2 + Vanilla JS, 로컬 전용, v0.2.4 완성 단계).
- **목적**: "메모 10개짜리 도구"를 넘어 사무실 개인 생산성 허브로 쓸 만한 빈 기능을
  리서치 합의 우선순위대로 채운다 — **무료 Peekom 이상**의 견고화 + 없는 기능의 신중한 추가.
- **사용자**: 개발자 본인 1인 + GitHub 무료 배포로 "Peekom Plus 기능을 무료로 쓰고 싶은
  소규모 사무실" 일반 Windows 사용자.
- **근거**: `research/guseok-memo-roadmap.md`(confidence: high),
  `research/raw/q01..q04.md`, `research/review/round-1.md`, `docs/IDEA.md`.

## 2. 핵심 흐름 (US)

- **US-01 검색→점프**: 사용자가 검색 진입점(전역키/트레이/버튼 — UI는 DESIGN 결정)을 열어
  키워드를 입력하면 10개 인덱스의 제목·본문 텍스트에서 매칭 목록이 나오고, 결과를 누르면
  해당 인덱스 메모 패널이 열린다.
- **US-02 리마인더**: 사용자가 인덱스에 시각(또는 반복 규칙)을 예약하면, 시각이 되면 알림이
  발생한다(OQ-02 방식 미정). 앱 재시작 후에도 예약이 유지된다.
- **US-03 폴더 동기**: 사용자가 저장 폴더를 OneDrive/Syncthing가 감시하는 위치로 지정하면,
  외부(다른 PC/동기 클라이언트)가 바꾼 store.json을 앱이 자동으로 다시 읽어 반영한다.
  계정·서버·클라우드 엔진 없이 로컬-퍼스트를 유지한다.

## 4. 기능 요구 (R-xx) — 관찰 가능한 수용 기준

### R-01 전체 검색 + 결과 점프 (P0)

- 검색 진입점을 연 뒤 키워드를 입력하면, **모든 인덱스(숨긴 인덱스 제외 — R-07 정책)의
  제목과 본문 텍스트**를 대상으로 매칭된 결과가 인덱스별로 나열된다.
- 각 결과에는 인덱스 제목과 매칭 전후 스니펫(문맥 발췌)이 보인다.
- 결과 항목을 누르면 해당 인덱스 메모 패널이 열린다(기존 `show_panel` 경로).
- 본문 검색은 HTML 태그가 아닌 **텍스트 내용**에 적용된다
  (`<div class="ck">` 안의 텍스트, `h1~h3`, `li` 포함).
- 매칭 0건이면 "결과 없음" 상태가 보인다. 빈 키워드면 검색을 수행하지 않는다.
- 이미지(`images[]`)는 검색 대상이 아니다.
- 검색 입력 중 IME 조합이 끊기지 않는다 (NFR-02 원칙 적용).
- 근거: q01·q03 독립 지목 최우선 공백, MS Sticky Notes Ctrl+F·Simple Sticky Notes
  Note Explorer 등 경쟁 앱 보편 기능.

### R-02 인덱스별 시각 리마인더 (P0)

- 사용자가 인덱스에 미래 시각 리마인더를 1개 이상 예약할 수 있다.
- 예약 시각 도래 시 알림이 발생한다 — 알림 방식(토스트/패널 강조/소리)은 **OQ-02(미정)**.
- 앱을 재시작해도 미래 리마인더가 유지되고 정상 발화한다 (store.json 영속).
- 재시작 시점에 이미 지난 리마인더는 자동 발화 대신 "놓친 알림"으로 구분 표시된다.
- 리마인더는 인덱스별로 설정·해제·목록 조회가 가능하다.
- 발화 시 패널이 닫혀 있어도 알림이 도달한다(트레이 상주 전제).
- 근거: q03 — Windows 무료/OSS 스티키노트의 구조적 공백(최다 불만),
  q01 — Stickies 알람 선례.

### R-03 반복 리마인더 (P1)

- 리마인더에 "없음/매일/매주" 반복 규칙을 지정할 수 있다.
- 반복 리마인더는 발화 후 다음 발생 시각이 자동 계산되어 계속 발화한다.
- 반복을 해제하면 더 이상 발화하지 않으며 과거 발화 이력은 남는다(또는 미보관 — 최소 구현).
- 근거: q03 — 데스크톱 스티키노트에서 희소(Stickies 반복 wake 선례) → 차별화.

### R-04 저장 폴더 위치 지정 (P1)

- 사용자가 설정에서 store.json의 저장 폴더를 임의 경로(예: OneDrive/Syncthing 폴더)로
  지정할 수 있다. 미지정 시 기존 `%APPDATA%\com.guseok.memo` 그대로.
- 지정 시 기존 store.json이 새 폴더로 이전(복사 후 검증, 원본 보존 또는 이동)되고,
  이후 저장·로드는 새 경로를 사용한다.
- 지정 해제(기본값 복귀)도 가능하다.
- 지정 폴더가 쓰기 불가·미존재이면 오류를 표시하고 기존 경로를 유지한다.
- 저장 위치 지정 상태가 앱 재시작 후에도 유지된다.
- 근거: q03 — Vovsoft "데이터 파일 위치" 요청, linuxmint/sticky #44, Joplin 파일시스템
  동기 선례.

### R-05 외부 변경 자동 리로드 (P1)

- 앱 실행 중 store.json이 **외부 프로세스(동기 클라이언트·다른 PC 기록분)** 에 의해
  변경되면, 앱이 변경을 감지해 자동으로 리로드한다.
- 리로드는 `migrate()` 경유로 정규화되어 모든 창(handles/panel/settings)에 기존
  `guseok://store` 전파 경로로 반영된다.
- 리로드가 편집 중인 에디터의 IME 조합이나 포커스를 깨지 않는다 (NFR-02).
- 감지 지연은 수 초 이내(측정: 변경 시각→반영 시각).
- 앱에 미저장 편집이 있는 동안 외부 변경이 감지된 **충돌 상황의 처리 정책은
  OQ-03(미정)** — 정책 확정 전까지 충돌 경로는 구현하지 않고 비충돌 경로만 확정한다.
- 근거: q03 — linuxmint/sticky #154(반응 수 최다 12, Syncthing 실사용),
  "동기 엔진을 만들지 말고 동기를 지원" 전략.

### R-06 템플릿/스니펫 (P1)

- 새 인덱스 생성 시 템플릿(빈/할일/회의 등 미리 정의된 본문)을 선택할 수 있다.
- 템플릿 적용 시 해당 HTML 본문이 새 인덱스의 `content`로 들어간다.
- 자주 쓰는 문구(스니펫)를 목록에서 골라 편집 중인 메모 커서 위치에 삽입할 수 있다.
- `{date}` 같은 치환자는 삽입 시 실제 값으로 치환된다.
- 템플릿·스니펫 정의는 store.json에 보존되며 기본 제공분이 있다(구성은 DESIGN/구현 시 확정).
- 근거: q03 — AdamKmet 템플릿·Espanso·iOS 템플릿 팩 선례, 반복 입력 절감.

### R-07 인덱스 표시/숨김 토글 (P1)

- 각 인덱스를 손잡이 스트립에서 숨길 수 있다(데이터·메모는 유지).
- 숨긴 인덱스는 스트립에 렌더되지 않고, 설정에서 다시 표시할 수 있다.
- 마지막 남은 1개(전부 숨김 상태)는 숨길 수 없다.
- 숨긴 인덱스는 Ctrl+번호 직접 열기·↑/↓ 순환 대상에서 제외된다.
- 숨김 상태는 store.json에 보존되고 재시작 후 유지된다.
- 근거: q03 — linuxmint/sticky #78(4 리액션) "show/hide notes", 10개 미만 사용자의
  손잡이 정리 수요.

### R-08 다크모드 (P1)

- 앱 크롬(설정 창, 패널 툴바·팝오버, 스트립 비인덱스 영역)에 라이트/다크/시스템 따르기
  모드를 적용한다 — **구체 색 방향·적용 범위는 docs/DESIGN.md 승인 대상**.
- 선택 모드는 store.json에 보존되고 재시작 후 유지된다.
- 메모 카드 자체의 배경·글자색은 인덱스별 테마(R-06 무관)가 그대로 우선한다 — 다크모드가
  사용자 지정 메모 색을 덮어쓰지 않는다.
- 근거: q03 — Simple Sticky Notes·MS·PinnyNotes 등 사실상 표준.

## 5. 비기능 요구 (NFR-xx)

- **NFR-01 저장 신뢰성**: 저장은 기존 임시파일→원자적 교체 방식 유지 + rename 점유 실패
  (백신·인덱서·동기 클라이언트) 시 짧은 재시도를 추가한다. `.bak` 백업 유지.
  검증: 점유 재현 환경에서 저장 성공/실패 로깅 확인, selftest `store-write` 통과 유지.
- **NFR-02 IME 품질 원칙**: 모든 신규 UI(검색창·리마인더 입력·외부 리로드 반영)에서
  **IME 조합 중 DOM/속성 변경 금지** — 조합 중에는 포커스된 에디터/입력의 속성·스타일·
  DOM을 바꾸지 않는다. 검증: CDP `imeSetComposition` 검사 + 실기 손 타이핑(OQ-05).
- **NFR-03 로컬-퍼스트**: 계정·서버·분석·광고 추가 금지. 유일한 네트워크 요청은
  GitHub Releases 업데이트 확인으로 유지. 동기는 OS 파일시스템 경유만(R-04/R-05).
- **NFR-04 스키마 호환**: store.json 스키마 버전을 명시하고, 구버전 파일·구버전 백업이
  `migrate()`로 정상 복원된다. 신규 필드는 기본값으로 채워져 구버전 앱이 읽어도 파괴 안 됨.
- **NFR-05 검증 게이트**: `npm run build` → `cargo fmt --check` → `cargo clippy -D warnings`
  → `cargo test` → debug exe `--selftest`(vite 선행) + `plan_setup/cdp-*.cjs` CDP 검증.
  신규 기능은 selftest 또는 CDP 스크립트 회귀 케이스를 동반한다.
- **NFR-06 창 수명**: 신규 창(검색 등)은 settings와 동일하게 setup에서 생성·hide/show
  재사용 원칙 — 런타임 커맨드 내 웹뷰 생성 금지(BUG-18 데드락 회귀 방지).

| 비밀값 | 비밀값을 코드·문서·커밋에 넣지 않는다. 필요 시 `$secret:NAME` 참조만. 서명 개인키(`~/.tauri/guseok-memo.key`, `TAURI_SIGNING_PRIVATE_KEY`)는 저장소에 두지 않는 기존 원칙 유지. | (사용자) |
| 자동시작·잔재 | 테스트로 등록한 시작프로그램·트레이·프로세스·임시 파일은 종료 전 원복·정리(전역 규칙). `--qa-autostart`는 기존 Run 값을 보존·복원해야 한다. | (사용자) |
