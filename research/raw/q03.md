# q03 — 데스크탑 스티키노트/메모 앱 사용자 요구 기능 트렌드 조사

- 조사일: 2026-11-18
- 대상 프로젝트: 구석메모 (Tauri 2 + Vite, 로컬 전용, 인덱스 10개, 리치텍스트/체크리스트/이미지/자동마크다운, 트레이, 전역단축키, 자동 업데이트)
- 방법: 유사 앱(Windows 스티키노트 중심)의 GitHub 이슈/토론, 벤더 기능요청 게시판, 공식 기능 페이지, 비교 기사를 조사. 실제 fetch한 페이지만 출처로 사용.

## 1. 수요 증거 요약

### 1.1 검색 / 전체검색 / 태그 / 핀

- Vovsoft(유료 스티키노트 벤더)의 사용자 투표 게시판에서 "Find (Ctrl+F) should work across all notes"가 3표로 상위권. 노트 1개 안이 아니라 **전체 노트를 가로지르는 검색**이 요구된다.
- Microsoft Sticky Notes는 공식적으로 Ctrl+F 전체 노트 검색을 지원하고, 2024년 OneNote 기반 신 버전은 **OCR로 이미지 속 텍스트까지 검색**, 원클릭 스크린샷 캡처, 자동 소스(출처) 캡처, 화면 가장자리 도킹, Win+Alt+S 전역 단축키를 넣었다. MS가 스티키노트 개선의 핵심으로 "찾기(search/recall)"를 택한 점이 시사적.
- Firefox 확장 stickynotes(kumabook)에는 "여러 태그로 검색 가능하게 해달라"(#146)는 요청이 있다. Notezilla는 태그/라벨로 그룹화·빠른 접근을 핵심 기능으로 판다.
- 핀/항상 위는 사실상 표준: PinnyNotes(131 stars, GPL-2.0, WPF)는 "핀=항상 위"가 앱 정체성이고, BetterStickies·Notezilla·Simple Sticky Notes 모두 always-on-top 제공. 구석메모의 인덱스-고정 UX와 유사한 가치.
- 메모 "숨기기/보이기 토글" 수요: linuxmint/sticky에 "show/hide notes" 옵션(#78, 4 리액션), 키바인딩 토글(#8), Show Desktop 시 접힘 문제(#24) 요청 — 전역 단축키로 전체 표시/숨김을 토글하는 패턴.

### 1.2 리마인더 / 알림 / 반복 체크리스트

- **가장 강한 신호 중 하나.** PinnyNotes 토론에서 유지자가 로드맵 1순위로 "Reminders(지정 시각 알림, 스누즈, 기한 경과 표시)"를 꼽았고, 사용자 댓글: "오픈소스 스티키노트를 다 써봤는데 **전부 리마인더가 없다**. 리마인더만 있으면 완벽" — Windows용 무료/OSS 스티키노트에서 리마인더가 구조적으로 빈 곳임을 보여줌.
- Vovsoft 투표판에 리마인더 관련 요청이 다수: "오래된 리마인더 삭제/숨김"(3), "리마인더 백업"(3), "리마인더 팝업에 날짜시각 표시"(3), "리마인더 소리"(2).
- 선행 사례:
  - Stickies(Zhorn, 프리웨어): 노트를 지정 시각까지 숨겼다 깨우는 "sleep", **매일/매주/매월 반복 wake** = 반복 리마인더, 알람음.
  - Simple Sticky Notes: 알람 기능 탑재(버전 히스토리상 알람 시간 선택기 버그 수정 이력).
  - Notezilla: 리마인더 알람이 핵심 셀링포인트(PC↔폰 동기 시 폰에서도 알림).
  - AdamKmet1997/sticky_notes(Electron, 8 stars): 노트별 리마인더 + 일/주 반복, 리마인더 인박스, OS 네이티브 알림.
  - BetterStickies: 노트 안에서 리마인더 설정, 긴급도별 색 변화(초록→주황→빨강).
- **반복 체크리스트(자동 리셋)** 는 모바일 생산성 앱에서 검증된 패턴: Tacklist(iOS)는 "매일/평일/매주 리셋 시각을 주면 모든 체크가 자동 해제"되는 "lists that reset themselves", DoRepeat는 반복 체크리스트 전용 앱(일/주/월 또는 완료 즉시 리셋). 스티키노트 쪽은 "Uncheck all" 수준(Android Sticky Notes Pro)까지가 대부분 — 데스크탑 스티키노트에서 자동 리셋은 차별화 여지가 큼.

### 1.3 동기화 — 로컬 퍼스트를 유지하며

- linuxmint/sticky의 **반응 수 1위 Feature Request(12 리액션)가 "notes.json이 디스크에서 변경되면 자동 리로드"**(#154). 사용자들이 이미 Syncthing/Seafile로 notes.json을 동기하고, Android 컴패니언 앱(styncy notes, GitLab)까지 만들어 쓰는 실측 사례. 결론: "동기화 엔진을 직접 만들 필요 없이 **파일 위치 지정 + 외부 변경 감지 리로드**만으로 Syncthing/OneDrive/NAS 조합의 로컬-퍼스트 동기가 성립".
- 같은 저장소에 "Nextcloud Notes와 동기화"(#2, Nextcloud Notes Android 앱 개발자가 직접 등록), "백업 폴더 선택"(#44, 4 리액션) 요청.
- Vovsoft 투표: "클라우드 동기화"(4표, 공동 1위) + "데이터 파일 위치를 사용자가 지정" (3표, 자동 백업 체계에 편입하기 위해서라는 이유 명시).
- PinnyNotes 로드맵에도 "Nextcloud 연동"이 올라 있음.
- Joplin의 설계 선례: 오프라인 퍼스트 + 동기화 대상을 **파일시스템(네트워크 디렉터리 포함)/Nextcloud/WebDAV/S3/Dropbox/OneDrive** 중 선택하게 함. "파일시스템 동기"가 첫 시민이라는 점에 주목 — 로컬-퍼스트 앱의 동기화는 폴더 하나를 싱크 대상으로 노출하는 것부터.
- 모바일 열람(수정 불가) 계열 선례:
  - ephe(GitHub, MIT, Rust+Tauri, ~900KB 단일 바이너리): PC가 로컬 HTTP+WebSocket 서버를 열고 QR을 띄우면 같은 Wi-Fi 폰에서 브라우저로 실시간 텍스트 공유. **Tauri로 QR 모바일 뷰를 만드는 직접적 기술 선례.**
  - NoteLAN(Obsidian 플러그인): 선택 노트를 LAN 내 읽기 전용 웹페이지로 서빙, 토큰 보호.
  - Beam/QrSendEasy/LocalSend 계열: QR→LAN 전송이 일반화된 UX 패턴.
- 과거 선례: Stickies는 TCP/IP 네트워크·SMTP로 노트를 다른 PC로 전송(2000년대부터 LAN 노트 공유가 존재했음).
- 반대 신호: Simple Sticky Notes는 동기화가 전혀 없고(로컬 파일 + 백업/복원만), 그 한계가 리뷰에서 단점으로 지적됨. MS Sticky Notes는 클라우드 동기를 넣었으나 "동기 실패·노트 유실"이 대표 불만 — **반쪽짜리 동기는 없는 것보다 평판이 나쁘다**는 점에서, 구석메모는 '동기 엔진'보다 '동기 친화적 저장(폴더 지정+리로드+충돌 방지)'이 현실적.

### 1.4 협업 없이 개인 생산성 향상 (템플릿/스니펫/클립보드)

- 템플릿: AdamKmet1997/sticky_notes는 빈/할일/회의 템플릿을 신규 노트 드롭다운·우클릭에서 제공. iOS Sticky Notes 앱들도 "Shopping List, Morning Routine…" 등 12종 템플릿 제공. Stickies는 서식 "스타일" 저장.
- 스니펫/텍스트 삽입: PinnyNotes 로드맵에 "날짜 스탬프 도구, Search&Replace(정규식)" 등 텍스트 도구. Espanso(GPL-3, 크로스플랫폼)는 ALT+Space 검색바로 스니펫/템플릿을 전 앱에서 삽입하는 대표 사례.
- Vovsoft 요청 중 흥미로운 것: "노트 내용을 지정 텍스트 파일에 날짜시각 스탬프와 함께 추가(append)" — 경비/할일/거래처별 누적 로그로 쓰고 싶다는 요구. 메모 → 장기 기록(로그)로 흘려보내는 가치.
- 클립보드 히스토리: Ditto(GitHub 7.4k stars, GPL-3, 활발) — 클립보드 이력 SQLite 저장, 즉시 검색, 그룹(=스니펫 라이브러리), PC 간 동기까지. Windows 표준 Win+V는 25개 제한이 단점으로 지적. **직접 만들기보다 Ditto 연동/위임하거나, "클립보드에서 바로 새 메모/인덱스로 붙여넣기" 수준이 실용적.**
- BetterStickies의 "paste anything"(스크린샷 인라인, 코드→코드블록, URL→링크, 파일→바로가기)은 자동마크다운을 이미 가진 구석메모와 방향이 같음.

### 1.5 접근성 / UX

- 다크모드는 이제 기본값: Simple Sticky Notes(v5.0, 2021)부터 PinnyNotes, MS Sticky Notes(설정→Color mode: Light/Dark/시스템), AdamKmet(라이트/다크/시스템)까지 전부 보유.
- 투명도/불투명도: linuxmint/sticky에 2건(#137, #157, 4 리액션), PinnyNotes·Simple Sticky Notes·BetterStickies는 이미 지원. 인덱스가 상시 화면 가장자리에 있는 구석메모에 특히 적합.
- 크롬 최소화: "타이틀바를 더 작게"(linuxmint #136/#139, macOS식 미니멀 요구), "Show Desktop 시 노트가 접히는 문제"(#24), 개별 노트 표시/숨김(#78/#153).
- 키보드 접근성: Microsoft는 Sticky Notes 전용 단축키 전체 표 + Narrator 스크린리더 가이드를 공식 문서로 유지 — 단축키 확장과 스크린리더 대응이 "완성도" 신호가 됨.
- 멀티모니터/가상데스크톱: linuxmint #67(보조 모니터 위치 문제, 9 리액션), #156(로그인 후 원래 데스크톱에 복원) — 위치/가시성 복원은 잔소리 같지만 반응이 많은 영역.
- 기타: 노트 잠금/보안 코드(Vovsoft 3표, linuxmint #138), 색 팔레트 편집(#125), 인쇄(#89), 날짜 표시 형식.

### 우선순위 추천 근거
- **P0 = 검색 + 리마인더**: 유사 생태계에서 "없어서 불만"인 두 기능. 구석메모의 "인덱스 10개" 구조는 검색이 없으면 오히려 약점(10곳을 사람이 뒤짐).
- **P1 묶음(3,4,5,7,8)**: 리마인더 인프라와 동기 친화 저장소가 서로를 키움. 특히 4+5 조합은 "동기화를 안 만들고 동기화를 지원하는" 최소비용 로컬-퍼스트 전략으로, linuxmint/sticky 사용자들이 수작업으로 하던 것을 제품화하는 것.
- **P2(9,10,11)**: 차별화·확장 영역. QR 뷰는 Tauri 선례(ephe)가 있어 기술 리스크가 낮은 편.
- **P3(12,13)**: 동기 엔진 직접 구현은 충돌/인증/회귀 비용이 커서, 폴더 동기 검증 후 수요가 확인되면 진행 권장.

## 4. 메모

- **구현 크기 추정 기준**: 구석메모가 Tauri 2(JS 프론트 + Rust 백)이므로 다크모드/검색은 프론트 중심(S~M), 리마인더·파일감시·LAN 서버는 Rust 관여(M), WebDAV 동기는 충돌해결 포함 L로 잡음. S=수일, M=1~2주, L=수주+.
- **"동기화를 만들지 말고 동기화를 지원하라"**: linuxmint/sticky #154와 Vovsoft "데이터 파일 위치" 요청이 같은 결론을 가리킴 — 저장 위치 지정 + 외부 변경 감지 리로드 + 내보내기 3종만으로 Syncthing/OneDrive/NAS/자동백업 생태계에 편입 가능. 클라우드 엔진·계정 없이 로컬-퍼스트 유지.
- **리마인더가 Windows 무료 스티키노트의 공백**: Notezilla(유료)·Simple Sticky Notes(프리웨어)는 있지만 OSS 계열(PinnyNotes, linuxmint sticky)은 거의 없음 → 구석메모가 넣으면 체감 차별화.
- **자동 리셋 체크리스트**는 모바일(Tacklist/DoRepeat)에서 검증됐고 데스크톱에선 희소. 구석메모의 체크리스트 + 리마인더를 합치면 "매일 아침 리셋되는 루틴 메모"라는 독특한 포지션 가능.
- **태그는 신중**: 인덱스 10개가 이미 분류 체계. 전면 태그 시스템보다 '인덱스별 색/상태 라벨 + 검색 필터'가 구조와 충돌하지 않음.
- **QR 모바일 뷰**는 읽기 전용으로 시작(협업/동기 아님)하면 범위 통제 가능. ephe가 Tauri+QR+WebSocket 선례라 기술 검증됨.
- 조사 한계: GitHub 이슈 반응 수는 표본이 작고 자기선택 편향이 있음. Vovsoft 투표는 유료 라이선스 보유자만 투표 가능. Microsoft Feedback Hub 내부 수요는 외부에서 확인 불가(공식 문서·출시 기능으로 대체 추정).
