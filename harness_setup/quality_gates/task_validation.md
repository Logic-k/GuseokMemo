# 게이트 — task_validation (독립 수용 관찰)

## 대상·근거

태스크의 `acceptance_criteria` 각 항목. lint/unit/e2e는 구현 세션 안의 검사고,
이 게이트는 **해당 변경을 구현하지 않은 별도 세션**이 기준을 실제 실행·관찰로
판정한다. 구현 세션의 자체 판정·보고로 대체할 수 없다.

## 규약

1. **세션 독립성**: 구현 대화·추론·"통과했다"는 결론을 상속하지 않은 세션.
   같은 모델 가능, 같은 세션의 역할 변경·구현 컨텍스트를 이어받은 자식은 불가.
   태스크마다 새 세션을 요구하지는 않되, 검증 대상 태스크의 구현 세션과는 분리한다.
2. **인계 항목** (조정자가 검증자에게 줄 것):
   - 태스크 파일 경로 — `acceptance_criteria`·`verification`·범위·차단 사유
   - 대상 코드 식별 — 관련 커밋/diff 또는 파일 목록 (열람 허용)
   - 필요 설계 — 해당 Architecture 절·TD·이벤트/데이터 계약
   - 실행 접속 — 본 문서의 실행 절차, vite :5183·CDP :9223·qa 로그 경로
   - 허용 데이터·권한 — store 스냅샷→복원, 자기가 띄운 프로세스만 종료, 잔재 정리
   - 잔여 예산·시간 상한
   - **인계 금지**: `STATE.md`/`LOG.md` 전체, 구현자의 추론·자체 판정, "통과 예상"
     같은 방향 유도. 운영 제약은 필요한 절만 발췌.
3. **검증자 제약**: 제품 코드·수용 기준·통과 단언(selftest/CDP 기대값)을 수정하지
   않는다. 검증자가 직접 고친 변경은 **다른 독립 검증자**가 판정한다.
4. **판정 방식**: 각 수용 기준을 실제 실행·관찰로 확인 —

   ```powershell
   powershell -File harness_setup/scripts/run-e2e.ps1 -Cdp "<태스크 지정 스크립트>"
   ```

   selftest 케이스·CDP로 부족한 기준(예: 트레이 상호작용, 실기 시각 확인)은 수동
   관찰 증거를 명시한다. 기준별로 `PASS / FAIL / 판정 불가(환경 문제)`를 내리고,
   FAIL·판정 불가는 **재현 절차와 관찰 증거**(로그 라인·CDP 출력·스크린샷)를 붙인다.
5. **반환 형식**: 기준별 판정 표 + 증거 + 마지막 줄 `RESULT: PASS|FAIL`
   (dod-runner 규약 — 없거나 FAIL이면 FAIL).
6. 테스트 재실행·코드 리뷰·구현자 보고만으로 PASS를 대신하지 않는다 — 기준마다
   **검증자가 직접 관찰한 증거**가 있어야 한다.

## 통과 조건

- 모든 `acceptance_criteria`가 기준별 관찰 증거와 함께 PASS.
- `판정 불가`가 남으면 게이트는 PASS가 아니다 — 환경 문제면 원인 해소 후 재판정,
  기준 자체가 실기 전용이면 phase-06 수동 검증으로 연결하고 태스크는 미완료 유지.

## 전제·활성 범위

- lint/unit/e2e 통과 후에만 연다 — 앞 게이트 실패 상태의 완료 판정 금지.
- blocked 태스크(DESIGN·OQ)는 차단 해제 전 이 게이트를 열지 않는다.
- 검증 세션도 동일 정리 규칙: 띄운 프로세스 종료·Run 키 원복·store 복원·임시 파일 정리.
